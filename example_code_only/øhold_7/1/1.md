We can use docker_compose.yml to automate creating multi-container applications

Docker_hub -> you dont have to make your own images

```

-- Beginning, one container --
docker build . -t <name>
docker run -p 5000:5000 <name>

-- If multiple containers --
docker compose up -d --build
docker compose down
docker compose down -v (also remove volumes! volume: mounts data in directory? for persistance)
	god idé at gøre, før man afleverer sit projekt


-d (background)
docker ps--all (show all containers, also not running)

-d detach (start containers in the background (good if slow))

```

Multiple Containers (Tiers) benefits
- e.g if we have aupdate to application, but not database
- take down container, start with new container
- But if we want the database to stay up, it is not necessary to take down
- **Make each part of the program independent!**

**Microservices:**
